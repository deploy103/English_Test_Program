# 회원가입 개인정보 처리 분석

작성일: 2026-07-06  
대상 프로젝트: English Test Program

이 문서는 회원가입 기능을 GitHub에서 바로 확인할 수 있도록 정리한 분석 메모입니다. 법률 자문은 아니며, 실제 서비스 공개 전에는 운영 형태와 대상 이용자에 맞춰 최종 검토가 필요합니다.

## 결론

이 프로젝트는 회원가입을 받을 때 개인정보 처리방침과 수집 항목 고지가 필요합니다.

다만 최신 개인정보보호위원회 안내 흐름상, 서비스 제공에 꼭 필요한 회원정보는 무조건 "필수 동의" 체크박스로 막기보다 개인정보 처리방침에 명확히 공개하고, 회원가입 화면에서 처리방침 링크와 처리 고지를 제공하는 방식이 더 적절합니다.

현재 코드 기준으로는 단순 회원정보뿐 아니라 접속기록, 보안 로그, 단어장, 시험 결과, 학습 기록도 사용자 계정과 연결되므로 개인정보 처리방침에 함께 포함해야 합니다.

## 현재 회원가입 수집 항목

회원가입 화면에서 직접 입력받는 항목:

- 이메일
- 아이디
- 이름
- 비밀번호

관련 코드:

- `src/main.ts`의 `renderRegisterForm`
- `server/auth.ts`의 `registerUser`
- `server/types.ts`의 `UserRecord`

서버에 저장되는 회원정보:

- 사용자 ID
- 아이디
- 이메일
- 이름
- 역할
- 비밀번호 해시
- 비밀번호 솔트
- 비밀번호 해시 파라미터
- 로그인 실패 횟수
- 잠금 해제 시각
- 계정 생성 시각
- 수정 시각
- 최근 로그인 시각

비밀번호 원문은 저장하지 않고 `scrypt` 기반 해시로 저장하고 있어 방향은 좋습니다.

## 자동 생성 또는 수집되는 정보

로그인과 세션 처리 과정에서 다음 정보가 저장됩니다.

- 세션 ID
- 세션 토큰 해시
- CSRF 토큰 해시
- 세션 생성 시각
- 세션 만료 시각
- 최근 접속 시각
- IP 주소
- User-Agent

감사 로그에도 회원가입, 로그인 실패, 비밀번호 변경 같은 이벤트와 함께 IP 주소, User-Agent가 기록될 수 있습니다.

처리방침에는 다음 문구가 필요합니다.

> 서비스 이용 과정에서 IP 주소, User-Agent, 접속 일시, 인증 및 보안 로그가 자동 생성되어 수집될 수 있습니다.

## 서비스 이용정보

이 앱은 영어 단어 학습 프로그램이므로 다음 정보도 계정과 연결됩니다.

- 사용자가 만든 단어장
- 업로드한 단어장 파일명
- 단어장 그룹
- 시험 결과
- 정답, 오답, 사용자 입력 답안
- 학습 통계

이 정보들은 일반적인 회원가입 정보는 아니지만, 특정 사용자와 연결되면 개인정보 처리방침에 포함하는 것이 안전합니다.

## 필수 수집 여부 검토

현재 필수 입력값 중 재검토가 필요한 항목은 `이름`과 `이메일`입니다.

아이디와 비밀번호는 계정 생성 및 로그인에 필요합니다.

이메일은 로그인 식별자, 계정 안내, 비밀번호 재설정 등에 사용한다면 필수로 설명할 수 있습니다. 다만 현재 프로젝트에 이메일 인증이나 비밀번호 재설정 기능이 없다면, 이메일을 필수로 받을 이유가 약해질 수 있습니다.

이름은 학교나 학급 관리 목적이 있으면 필수로 둘 수 있습니다. 개인 학습용 서비스라면 이름 대신 닉네임으로 바꾸거나 선택 항목으로 낮추는 것이 개인정보 최소수집 원칙에 더 맞습니다.

권장 방향:

- 학교/관리자용 서비스라면 이름 필수 유지 가능
- 개인 학습용 서비스라면 이름을 닉네임으로 변경하거나 선택 항목화
- 이메일을 필수로 유지한다면 처리 목적을 명확히 적기

## 회원가입 화면에 필요한 고지

회원가입 버튼 근처에 다음 정도의 문구와 링크를 넣는 것이 좋습니다.

```text
회원가입 시 계정 생성, 로그인, 학습 기록 관리, 보안 관리를 위해 개인정보가 처리됩니다.
자세한 내용은 개인정보 처리방침을 확인하세요.
```

여기서 `개인정보 처리방침`은 별도 페이지나 문서로 연결합니다.

필수 체크박스를 넣을 수도 있지만, 서비스 제공에 필요한 개인정보에 대해 형식적인 필수 동의 체크박스를 강제하는 방식은 최신 개선 방향과 어긋날 수 있습니다. 대신 처리방침 공개와 명확한 고지가 중요합니다.

## 개인정보 처리방침에 들어갈 항목

최소한 다음 항목을 넣어야 합니다.

- 개인정보의 처리 목적
- 처리하는 개인정보 항목
- 개인정보의 처리 및 보유기간
- 개인정보의 파기 절차와 방법
- 개인정보 제3자 제공 여부
- 개인정보 처리 위탁 여부
- 정보주체와 법정대리인의 권리 및 행사 방법
- 개인정보의 안전성 확보조치
- 개인정보 보호책임자 또는 문의처
- 자동 수집 장치 사용 여부
- 처리방침 변경 시 고지 방법

현재 프로젝트 기준 예시는 아래와 같습니다.

### 처리 목적

- 회원가입 및 계정 관리
- 로그인 및 사용자 인증
- 단어장 저장 및 학습 기능 제공
- 시험 결과 저장 및 학습 통계 제공
- 부정 이용 방지 및 보안 로그 관리
- 관리자 기능 제공

### 처리 항목

필수 회원정보:

- 아이디
- 이메일
- 이름 또는 닉네임
- 비밀번호 해시 정보

자동 생성 정보:

- IP 주소
- User-Agent
- 접속 일시
- 세션 정보
- 인증 및 보안 로그

서비스 이용정보:

- 단어장
- 단어장 파일명
- 시험 결과
- 답안 입력 내역
- 학습 통계

### 보유기간

정책 예시:

- 회원정보: 회원 탈퇴 시까지
- 단어장 및 학습기록: 회원 탈퇴 시 또는 사용자가 삭제할 때까지
- 인증 및 보안 로그: 보안 사고 대응과 부정 이용 방지를 위해 일정 기간 보관
- 법령상 보관 의무가 있는 정보: 해당 법령에서 정한 기간

실제 구현에서는 탈퇴 기능과 데이터 삭제 기능이 보유기간 정책과 맞아야 합니다.

## 만 14세 미만 이슈

교육용 서비스라면 학생 이용 가능성을 고려해야 합니다.

만 14세 미만 아동의 개인정보를 처리하려면 법정대리인 동의 문제가 생깁니다. 현재 프로젝트가 법정대리인 동의 절차를 구현하지 않는다면, 초기에는 회원가입 화면에 만 14세 이상만 가입 가능하다는 정책을 두는 방식이 현실적입니다.

권장 문구:

```text
만 14세 미만은 보호자 또는 법정대리인의 동의 없이 가입할 수 없습니다.
```

더 단순하게 운영하려면:

```text
이 서비스는 만 14세 이상만 가입할 수 있습니다.
```

## 보안 상태 메모

현재 코드에서 긍정적인 부분:

- 비밀번호 원문을 저장하지 않음
- `scrypt` 기반 비밀번호 해시 사용
- 세션 토큰과 CSRF 토큰을 해시로 저장
- 쿠키에 `httpOnly` 적용
- 쿠키에 `sameSite: Strict` 적용
- 로그인 실패 횟수와 계정 잠금 처리 존재
- 감사 로그 존재

추가로 점검할 부분:

- 개인정보 처리방침 페이지 추가
- 회원가입 화면에 처리방침 링크 추가
- 탈퇴 기능과 개인정보 삭제 범위 정리
- 관리자 계정의 개인정보 접근 범위 정리
- 보안 로그 보유기간 정리
- 운영 환경에서 HTTPS 강제 여부 확인
- 백업 데이터 보관 및 파기 기준 정리

## 구현 우선순위

1. 개인정보 처리방침 문서 또는 페이지 추가
2. 회원가입 화면 하단에 처리방침 안내 문구와 링크 추가
3. 이름 필수 여부 재검토
4. 이메일 필수 여부와 사용 목적 재검토
5. 만 14세 미만 가입 정책 결정
6. 탈퇴 및 개인정보 삭제 정책 정리
7. 보안 로그 보유기간 정리
